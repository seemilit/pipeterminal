# 文件传输

连接服务器后，Shell 右上角的“文件传输”打开本地与服务器双栏窗口，固定为 1040×640。“传输列表”（原“上传/下载”）打开另外一个 360×330 的无系统标题栏小窗，靠近右上角按钮显示，主窗口移动、调整大小时保持定位，并限制在屏幕可用区域内。布局主要参考原 `ssh/app/qt_ssh_terminal_view.py` 中的 `_DownloadTaskPanel`：标题栏显示任务数量和小按钮，正文按卡片显示名称、16 像素进度条和状态。任务多时滚动显示。两个窗口可以同时显示，任务为空时也不缩小、不自动隐藏；隐藏传输列表不会关闭 FTP 窗口或取消传输。窗口按需创建，不增加独立左侧菜单。

终端命令栏右侧“▲”展开下方服务器文件面板，按钮变为“▼”后可收起。面板左侧是服务器目录树，右侧是当前目录的文件列表，默认隐藏，可拖动终端与文件区之间的分隔线调整高度，最小高度 260。文件列表和传输任务使用同一面板内的两个页签，空任务列表不会使面板收缩。下方面板提供目录导航、选择目录、刷新和任务页，不显示上传、上传文件夹、下载按钮行；文件传输操作从弹窗进行。终端 `cd` 后按确认的工作目录更新下方列表；从终端路径链接跳转成功时同步更新列表和目录树。

弹窗和下方面板分别持有 `FileTransferWorkspace`，各自浏览目录，共享同一传输队列、任务进度和取消/清除操作。打开右上角窗口不会移动下方面板，也不会使其收起，两边可以同时显示。目录读取各自使用后台任务，复制任务只执行一次；共享队列的覆盖确认只弹一次。收起面板或关闭弹窗不会取消任务，断开连接时收起下方列表并取消任务；重连不主动展开列表。

独立的传输列表只持有共享队列的视图，不创建文件浏览区或新的传输队列。
卡片的取消、清除与文件工作区的任务页同步。每项的 × 在传输中取消任务，
结束后移除该条记录；取消过程中暂时禁用。顶部可以取消全部任务或清除
已结束记录，— 隐藏窗口。下载成功后，文件夹按钮可打开本地保存目录。
长名称和路径放入提示信息，所有文案支持现有六种语言，颜色沿用当前主题。

传输卡片的名称、进度条和状态区域支持右键菜单。下载任务可打开本地保存
文件夹；上传任务可「定位到服务器目录」，展开下方文件面板并切换到该任务
的远端目标目录，终端不执行 cd。已完成的上传定位后会选中对应顶层文件或
文件夹；传输中的任务只定位目录，不主动选中文件。断开或重连后，旧连接
任务的远端定位不可用，本地目录仍可打开。右键还提供取消传输或移除结束记录。

上传成功时，若下方当前请求/显示的目录就是任务目标目录，沿用上传完成后的
目录刷新，在最新列表绘制完成后选中实际上传的条目；不会强制展开面板或
跳到其他目录。失败、取消、覆盖确认时跳过的普通文件不会触发自动选中。
批量上传支持多选，上传文件夹选中顶层目录，不把最后一个子文件当作根目录
里的文件。目标使用 SFTP 确认的完整路径，定位和选中不会依赖当前进度文件名。

`basic/sftp` 是与 Connection、Shell、Terminal 平级的独立 package，只有 `module.py` 向 Registry 注册工厂和翻译。Shell 按模块 ID 获取工厂；删除整个 SFTP package 后，Shell 仍可连接和显示终端，这两个入口不可用。

## 使用

- 左侧浏览本地文件，右侧浏览服务器文件；路径栏可输入目录，双击文件夹进入，上一级和刷新用于导航。
- 服务器文件面板内部左侧提供从 `/` 展开的目录树，宽度参考原项目为 150–280，可拖动树和文件列表之间的分隔线调整。仅显示文件夹，展开分支时按需在后台读取子目录；单击树中的目录打开右侧列表。当前目录会自动定位、展开祖先并选中；列表已经取得的数据复用于该目录分支，读取失败的分支可再次折叠、展开重试。弹窗与下方面板各有自己的目录树，重连后清除上一连接的树数据。
- 右侧“选择目录”打开服务器文件夹选择窗，只显示文件夹。可以选中某个文件夹，也可以进入目录后使用当前目录；点击“确定”才切换右侧路径，取消保留原路径。目录查询在后台进行，断开连接时关闭选择窗。
- 在左侧选择文件或文件夹，点击“上传 →”，放到右侧当前显示的服务器目录下。
- 在右侧选择文件或文件夹，点击“← 下载”，放到左侧当前显示的本地目录下。
- 两侧文件列表支持互相拖拽，复用相同上传/下载队列。拖到文件夹行时传入该文件夹，拖到文件行或空白处时传入当前目录；只执行复制，保留源文件。支持多选及文件夹，进度和覆盖确认与按钮操作一致。断开、重连、读取目录期间以及文件夹选择窗内不接受传输拖拽；不接受来自其他服务器窗口的拖拽。
- 支持多选、递归文件夹和空文件夹。服务器目录尚未读取成功时，不允许开始传输。
- 下方面板跟随终端确认的工作目录；首次打开弹窗使用下方面板当前请求的目录，后续独立浏览目录。
- 同名普通文件逐个询问是否覆盖：是为覆盖，否为跳过，取消为停止整个任务。目录与文件类型冲突直接报告失败。
- 传输任务显示方向、当前文件、进度和结果；可取消单个或全部任务，可清除已结束的任务记录。清除记录不删除文件。
- 关闭传输窗口只隐藏窗口，任务继续；断开、重连、关闭 Shell 标签或退出程序会取消该连接的任务。已经完成的文件保留。

## 结构与数据流

- `browser.py`：本地 QFileSystemModel 和远端目录树／文件列表的布局、分批显示和输入时的绘制让步。
- `directory_tree.py`：`RemoteDirectoryTree.bind_session` 绑定当前连接，`sync_directory` 定位当前目录并复用列表数据；`_expanded`、`_enqueue`、`_advance` 串行读取并分批绘制目录分支，`_failed` 支持失败重试，`shutdown` 停止自己的查询。`_items`、`_cache`、`_loaded`、`_pending`、`_loading`、`_rendering` 保存节点、缓存、队列和绘制状态。
- `drag_drop.py`：配对文件视图的复制拖拽、连接标记校验和落点识别，不通过本地文件模型移动或删除源文件。
- `workspace.py`：独立文件界面与共享传输队列的任务视图；只有队列所属界面处理覆盖确认。弹窗显示本地与服务器双栏，嵌入时显示服务器目录树和列表，所有 QWidget 操作在 Qt 主线程。
- `dialog.py`：创建固定大小的独立弹窗和下方界面；`directory_picker.py`：独立的远端文件夹选择窗。
- `task_list.py`：工作区内的任务表格；`task_cards.py`：独立小窗的紧凑任务卡片；`task_dialog.py`：固定大小、右上角定位的传输列表小窗口。
- `TransferTask.remote_directory`、`remote_targets`、`uploaded_paths`：仅在内存里记录实际目标目录、顶层目标和成功上传的顶层条目，不修改服务器配置文件格式。
- `controller.py`：单任务传输队列、独立目录查询、进度节流和过期查询结果处理；`listing_failed` 通知目录树处理当前分支的失败，不改变已有列表的错误提示。
- `backend.py`：后台打开 SFTP 通道、递归收集文件、字节传输和临时文件提交，不导入 Qt。
- `model.py`：目录、计划和任务数据，跨线程取消使用 Event。
- `translations.py`：简体中文使用源文案，提供英语、繁体中文、日语、韩语、西班牙语翻译。

Shell 的 `SSHSession.connection_context()` 只提供已认证 Transport 和本次连接的停止标记，不暴露密码，不重复登录。每个浏览或传输任务打开自己的 SFTP channel，只关闭自己持有的 channel，不读取终端的 PTY channel。仍共享 SSH 连接的网络带宽。

同一窗口一次执行一个传输任务，其他任务排队；文件列表目录查询可独立进行，每次只保留最新请求。目录树有独立查询控制器，待展开分支按队列串行读取，断线后丢弃旧结果。网络操作在后台线程执行，通道打开超时 5 秒，SFTP 初始化和通道 I/O 超时 15 秒；取消检查线程关闭该任务的通道以中断等待。进度更新约每 100 毫秒一次；目录树和远端列表只在可见时绘制，每批最多 100 项、约 4 毫秒预算，终端输入时短暂延后绘制。

上传先写唯一的 `.part` 文件，检查大小后提交；覆盖现有文件使用服务器的 POSIX rename 扩展，并保留原文件权限。没有该扩展的服务器可上传新文件，但覆盖失败，不会先删除旧文件。下载先写同目录临时文件，大小一致后替换最终文件。传输失败或取消会尽力清理本次临时文件；连接已断开时，服务器上可能留下临时文件。已提交的其他文件不会回滚。

上传下载仍不传输链接、目录联接和特殊文件，防止递归循环或写出目标目录。下载时校验服务器文件名与本地路径；Windows 不合法的文件名直接报告失败，不静默改名。文件列表和目录树现已提供右键菜单，包括新建、重命名、删除、远端复制剪切粘贴、文本编辑、文件权限、脚本和日志操作。详情见 [file-actions.md](file-actions.md)。暂不提供断点续传或额外文件操作快捷键；编辑器支持 Ctrl+S 保存。

安装日志模块时，每个执行的任务生成 `conf/.logs` 下的 SFTP 日志，记录方向、路径和结果，不记录文件内容或认证信息。

打包脚本已经按 package 动态收集 `basic` 子模块，因此无需增加新的打包规则或第三方依赖。本次仅做源码检查，未运行项目、测试、打包或真实服务器传输；大文件、网络断开、目录合并、覆盖确认和服务器权限仍需实机验收。

参考：[Paramiko SFTP API](https://docs.paramiko.org/en/stable/api/sftp.html)、[Transport channel API](https://docs.paramiko.org/en/stable/api/transport.html)。
